# Hulma Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Hulma, a single Next.js app on Cloud Run in which Gemini interviews a business owner, designs a validated blueprint, and one generic engine turns it into a working booking, POS, finance, HRIS or social media system inside that owner's dashboard, with safe previewed changes and undo.

**Architecture:** Pure TypeScript core (blueprint, formula language, change ops) with no I/O, plus an engine over Postgres JSONB records and an AI layer that only ever emits ChangePlans validated by the core. The UI renders every view and widget from the current blueprint. AI calls run live or from recorded fixtures.

**Tech Stack:** Node 22, pnpm, Next.js (App Router, standalone output), React 19, TypeScript strict, Tailwind CSS v4, Zod 4, jsep, Drizzle ORM (node-postgres in prod, PGlite in tests), @google/genai (Vertex AI), Recharts, cmdk, @phosphor-icons/react, geist font, Vitest, Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-13-hulma-design.md` (section numbers below are §n of that spec).

## Global Constraints

- Submission deadline 2026-10-18. Team formation deadline 2026-10-14.
- Deployed on Cloud Run, region asia-southeast1. Gemini via Vertex AI only (service account, no API keys in code).
- The AI never writes or executes code. Every AI output is a Zod-validated object, and blueprint changes go through `validateBlueprint`.
- Timezone Asia/Manila for all date logic. Currency PHP (₱), money rounded to 2 decimals.
- Ids are lowercase snake_case; `owner` role always exists with full permissions.
- Default model `gemini-3.8-flash` (env `GEMINI_MODEL`), Vertex location `global`; `ARCHITECT_MODEL` optional override.
- `AI_MODE=live|fixtures|record`; every test and E2E run uses `fixtures`.
- UI tokens: shell #0E0E10, panel #141416, hairline #232326, text #E6E6E8, muted #8A8A93, accent #3FA796, warning #D4A24C. Geist Sans 13px, Geist Mono for numbers/times/ids. 32px rows. No pure black, gradients, glows or emoji. Icons from @phosphor-icons/react only.
- Motion: ⌘K opens without animation; panes/dialogs 180–220ms `cubic-bezier(0.23,1,0.32,1)`; buttons `scale(0.98)` on press.
- Out of scope (spec §15) stays out until 18 Oct.

## Review Focus

1. **Bookings at boundaries:** back-to-back slots (18:00–19:00 then 19:00–20:00) must be allowed; a booking crossing closing time or midnight must be rejected with a clear message. Test in Task 5.
2. **Changing a price must not rewrite paid history:** frozen formula values stay put through blueprint changes, impact and undo. Test in Task 10.
3. **Undo after someone edited the record:** undo must not overwrite a newer manual edit, and must report it. Test in Task 10.
4. **Hidden fields leaking through AI or charts:** salary-type fields must not appear in Operator answers or aggregates for staff. Tests in Tasks 7 and 16.
5. **Model returns almost-right JSON:** unknown field ids, a missing status option or a formula cycle must trigger the repair loop and never reach the database. Test in Task 12.
